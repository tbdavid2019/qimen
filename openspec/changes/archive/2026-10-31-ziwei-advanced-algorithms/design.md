# Design

## Context

參閱 `proposal.md`。當前系統的紫微斗數邏輯集中於 `lib/ziwei.js`（約 1000 行），具備真太陽時校驗、排盤與兩個特色衍生算法（男生尺寸與未來另一半）。本設計旨在模組化拆分高階算法，確保零構建依賴、高可維護性與向下相容性。

## Goals / Non-Goals

**Goals:**
- **模組化分工**：將 34 種格局拆分為 `lib/ziwei-patterns.js`，十二神煞拆分為 `lib/ziwei-shensha.js`，雙盤合婚拆分為 `lib/ziwei-match.js`，由 `lib/ziwei.js` 統一調度匯總。
- **100% 原生相容**：全模組使用標準 CommonJS，不引入任何新的 npm runtime 依賴，維持 Node.js 26+ 與 Vercel Serverless 冷啟動零負擔。
- **向下相容契約**：既有 API 欄位保持完整，原 `patterns` 陣列升級為富結構物件，並保留 `name`、`desc`、`type` 等別名以保證既有客戶端無痛升級。
- **5 層端到端對齊**：Web UI、API、CLI、WebMCP、文檔全部同步更新。

**Non-Goals:**
- 不引入外部大型資料庫（PostgreSQL / Redis）；所有排盤、格局匹配與合盤評估均為確定性即時純函數計算。
- 不引入 56GB 靜態文本語料庫；維持理性算力與即時 LLM 智慧分析相結合。
- 不使用非商用授權之倪師影片逐字稿，僅採用公版古籍經文與理性客觀斷語。

## Decisions

### 1. 拆分獨立算法模組而非單一肥大文件
- **決策**：新增 `lib/ziwei-patterns.js`、`lib/ziwei-shensha.js`、`lib/ziwei-match.js`。
- **替代方案**：全部塞入 `lib/ziwei.js`。
- **理由**：34 個格局判定邏輯長達上千行，獨立模組利於單元測試、單獨維護與權責分離。

### 2. 善本星曜廟旺平陷校驗
- **決策**：在 `lib/ziwei.js` 中直接修正 `STAR_BRIGHTNESS`，覆蓋太陰、天機、天府等 24 處分歧，並在代碼註釋中標明《紫微斗數全書》善本依據。
- **理由**：排盤是底層基石，統一善本標準能確保所有後續格局判定與三方四正分析完全準確。

### 3. 格局資料結構設計（分層條件）
- **決策**：
  ```javascript
  {
    name: '君臣慶會',
    level: 'excellent', // 'excellent' | 'good' | 'neutral' | 'caution'
    type: '吉格', // 向下相容
    desc: '紫微得群星拱照，領導才能卓越...',
    palaces: ['命宮', '官祿宮', '財帛宮'],
    conditions: {
      required: ['紫微坐命', '會照左右昌曲魁鉞'],
      bonus: ['三方見雙祿'],
      breaking: []
    },
    source: '《骨髓賦》'
  }
  ```
- **理由**：既向下相容既有前端與測試，又能讓新版 UI 呈現「成格/加分/破格/典籍」四位一體大師級質感。

### 4. 雙盤合婚算法架構
- **決策**：接收雙方生辰與性別，內部各起一張命盤，比對：
  1. 雙方命宮主星生剋與互補性（30%）
  2. 夫妻宮星曜投射（雙方性格是否符合彼此夫妻宮正緣畫像）（30%）
  3. 生年四化互照（祿/權/科照入對方三方四正為加分，忌星衝破為扣分）（25%）
  4. 夫妻宮對衝煞星與刑克（15%）
  計算 0-100 綜合契合指數與理性相處指南。

## Risks / Trade-offs

- **[Risk]** 格局判定條件繁多，可能在特定命盤上產生邊界情況或極端破格。
  → **Mitigation**: 建立包含歷史名人盤與極端盤（如命無正曜、多煞交加、全吉星）的全面回歸測試套件，確保 100% 測試覆蓋率。
- **[Risk]** 神煞過多可能導致手機端盤面視覺擁擠。
  → **Mitigation**: Web UI 採用「主星/輔星 + 折疊或小膠囊標籤神煞」，預設呈現重要主煞，點擊可展開歲前/將前/博士十二神。
